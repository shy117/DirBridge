# 运行环境说明

关联：[CMake 依赖方案](CMake依赖方案.md)、[三方库管理](三方库管理.md)

## 目标

`build/run` 是本地可直接运行目录，用于快速验证当前构建产物。它不提交到 Git，随时可以重新生成。

当前可执行文件：

```text
<项目目录>\build\run\DirBridge.exe
```

## 生成步骤

先构建 Debug 版本：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_third_party.ps1
cmake --preset windows-mingw-debug
cmake --build --preset windows-mingw-debug
```

创建运行目录并复制 DirBridge 与 libcurl 运行文件：

```powershell
New-Item -ItemType Directory -Force build\run
Copy-Item -Force build\windows-mingw-debug\DirBridge.exe build\run\DirBridge.exe
Copy-Item -Force build\windows-mingw-debug\libcurl-x64.dll build\run\libcurl-x64.dll
Copy-Item -Force build\windows-mingw-debug\curl-ca-bundle.crt build\run\curl-ca-bundle.crt
```

使用 `windeployqt` 补齐 Qt 和 MinGW 运行库：

```powershell
windeployqt.exe --compiler-runtime --no-translations build\run\DirBridge.exe
```

如果 `windeployqt.exe` 不在当前终端 `PATH` 中，请先按本机 Qt 安装位置配置 PATH，或在本机私有的 `CMakeUserPresets.json` 中维护相关环境。

## 验证命令

在运行目录中直接执行，不额外设置 Qt 路径：

```powershell
Set-Location <项目目录>\build\run
.\DirBridge.exe --check-curl
.\DirBridge.exe --check-deps
.\DirBridge.exe --smoke-test
.\DirBridge.exe --ui-remote-smoke-test
.\DirBridge.exe --ui-remote-workflow-smoke-test
.\DirBridge.exe --ui-remote-live-smoke-test
.\DirBridge.exe --ui-remote-live-refresh-smoke-test
.\DirBridge.exe --ui-remote-live-transfer-smoke-test
.\DirBridgeCoreChecks.exe
```

已配置 CMake 的构建目录还可以运行不依赖真实服务器的 Core 检查：

```powershell
ctest --test-dir <构建目录> --output-on-failure
```

当前默认 CTest 只注册 `DirBridgeCoreChecks`。需要图形会话的 UI smoke test 和依赖 `DIRBRIDGE_TEST_*` 环境变量的真实 FTP/SFTP 联调仍按下文命令单独运行。

`--check-curl` 应输出 libcurl 协议列表，并包含：

```text
ftp
sftp
```

`--smoke-test` 应能启动空 Qt 窗口并自动退出。

`--ui-remote-smoke-test` 应确认主界面远程工作流基础控件存在：

- 快速连接协议、主机、端口、用户名、密码、远程路径和连接按钮。
- 远程地址栏。
- 远程文件树。
- 远程文件列表。
- 远程状态标签。
- 底部传输表，且至少有一条初始任务行。
- 底部日志表。

`--ui-remote-workflow-smoke-test` 使用内存型远程后端，不访问真实服务器，应确认：

- 快速连接后远程状态显示已连接。
- 当前远程路径保持为 `/home/testuser/remote_test`。
- 远程文件列表显示测试目录和文件。
- 双击远程目录后地址栏进入子目录。
- 返回上级后回到 `/home/testuser/remote_test`。
- 断开后远程面板回到未连接状态，不保留旧路径。
- 连续创建两个远程标签页时，每个标签页保留独立路径和连接状态，断开当前标签页不会影响其他已连接标签页。

`--ui-remote-live-smoke-test` 使用 `DIRBRIDGE_TEST_*` 环境变量连接真实 FTP/SFTP 服务器，应确认：

- 主窗口快速连接能连接真实远程服务。
- 远程状态标签显示已连接。
- 远程地址栏保持 `DIRBRIDGE_TEST_PATH`。
- 远程列表显示测试目录，默认检查 `download`、`edit`、`update`，可通过 `DIRBRIDGE_TEST_EXPECTED_DIRS` 覆盖。
- 双击远程目录后进入子目录，点击上级后回到 `DIRBRIDGE_TEST_PATH`。
- 触发断开后远程面板复位，不继续保留旧路径。

`--ui-remote-live-refresh-smoke-test` 使用 `DIRBRIDGE_TEST_*` 环境变量连接真实 FTP/SFTP 服务器，应确认：

- 主窗口快速连接成功后，外部后端在当前远程目录新建测试目录。
- 点击远程面板刷新按钮后，远程列表显示新目录。
- 外部后端删除测试目录。
- 再次点击远程面板刷新按钮后，远程列表不再显示该目录。

`--ui-remote-live-transfer-smoke-test` 使用 `DIRBRIDGE_TEST_*` 环境变量连接真实 FTP/SFTP 服务器，应确认：

- 主窗口快速连接成功后，上传一个临时小文本文件到当前远程目录。
- 底部传输表出现“上传 / 已完成”任务。
- 远程列表刷新后可见上传文件。
- 从远程下载该文件，底部传输表出现“下载 / 已完成”任务。
- 验证结束后删除远程临时文件。
- `--ui-remote-workflow-smoke-test` 还会通过内存型远程后端验证本地文件夹递归上传、远程文件夹递归下载、远程内部移动和非空远程文件夹递归删除。

`--check-deps` 应确认：

- libcurl 支持 `ftp` 和 `sftp`。
- nlohmann/json 可序列化和解析配置对象。
- spdlog 可写入当前运行目录下的 `logs/dirbridge.log`。
- 站点配置可写入当前运行目录下的 `config/sites.json`。

`DirBridgeCoreChecks.exe` 应确认：

- 内存型远程后端可连接、列目录、新建目录、新建空文件、删除、重命名、上传、下载。
- 内存型远程后端对断开连接、重名、缺失路径、非空目录、非法下载目标等失败路径返回明确错误。
- `TransferJob` 上传/下载方向、状态和进度计算正常。
- `TransferQueue` 和 `TransferManager` 可入队、取消、重试、清理已完成任务、按默认并发限制调度，成功、失败和取消任务会保留终态与错误信息。

## 远程集成验证

`DirBridgeRemoteCheck.exe` 用于真实 FTP/SFTP 服务器验证。它只从环境变量读取连接信息，不在源码或文档中保存密码。写入验证会覆盖列目录、新建目录、目录重名错误、新建空文件、文件重名错误、重命名、上传、下载、删除文件和删除目录。

必填环境变量：

```powershell
$env:DIRBRIDGE_TEST_PROTOCOL='sftp'  # sftp 或 ftp
$env:DIRBRIDGE_TEST_HOST='<测试服务器 IP 或域名>'
$env:DIRBRIDGE_TEST_PORT='22'
$env:DIRBRIDGE_TEST_USER='testuser'
$env:DIRBRIDGE_TEST_PASSWORD='<在本机临时设置>'
$env:DIRBRIDGE_TEST_PATH='/home/testuser/remote_test'
```

只读验证：

```powershell
.\DirBridgeRemoteCheck.exe
```

写入和传输验证：

```powershell
$env:DIRBRIDGE_TEST_ALLOW_WRITE='1'
.\DirBridgeRemoteCheck.exe
```

只验证文件上传、下载、删除，跳过目录新建和重命名：

```powershell
$env:DIRBRIDGE_TEST_ALLOW_WRITE='1'
$env:DIRBRIDGE_TEST_FILE_ONLY='1'
.\DirBridgeRemoteCheck.exe
```

清理远程测试残留项：

```powershell
$env:DIRBRIDGE_TEST_CLEAN_PREFIX='dirbridge_check_'
$env:DIRBRIDGE_TEST_CLEAN_ONLY='1'
.\DirBridgeRemoteCheck.exe
```

注意：`config/` 和 `logs/` 生成在进程当前工作目录下。验证 `build/run` 可运行环境时，应先 `Set-Location` 到 `build/run` 再启动程序。

如果测试站点已经保存在当前运行目录的 `config/sites.json` 中，也可使用下列只读连接检查。该检查复用当前 Windows 用户的 DPAPI 凭据，不需要将密码写入环境变量：

```powershell
.\DirBridge.exe --ui-saved-site-smoke-test "<已保存站点名称>"
```

如果 `build/windows-mingw-debug` 中仍保留旧路径的 CMake cache，又暂时不想重建 `build/run`，可以新建临时验证目录，仅用于本地编译检查。下面命令中的 Qt 和 MinGW 路径请替换为本机实际路径：

```powershell
cmake -S . -B build\verify -G "MinGW Makefiles" `
  -DCMAKE_BUILD_TYPE=Debug `
  -DCMAKE_PREFIX_PATH=<Qt 安装目录>/mingw_64 `
  -DCMAKE_MAKE_PROGRAM=<MinGW 工具目录>/bin/mingw32-make.exe `
  -DCMAKE_C_COMPILER=<MinGW 工具目录>/bin/gcc.exe `
  -DCMAKE_CXX_COMPILER=<MinGW 工具目录>/bin/g++.exe `
  -DDIRBRIDGE_THIRD_PARTY_ROOT="$PWD/third_party/installed" `
  -DDIRBRIDGE_CURL_ROOT="$PWD/third_party/installed/curl" `
  -DDIRBRIDGE_JSON_ROOT="$PWD/third_party/installed/nlohmann_json" `
  -DDIRBRIDGE_SPDLOG_ROOT="$PWD/third_party/installed/spdlog"
cmake --build build\verify
```

这个目录同样位于 `build/` 下，不提交到 Git。

当前项目名和可执行文件名为 `DirBridge`。外层源码目录名不影响 CMake 项目名和可执行文件名。

## Git 策略

`build/` 和 `third_party/` 已在 `.gitignore` 中排除：

```text
build/
third_party/
```

因此运行目录和下载的二进制依赖都不提交，只提交构建脚本、源码和文档。

运行时生成的 `config/` 和 `logs/` 也不提交到 Git。
