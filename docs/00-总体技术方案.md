# 00-总体技术方案

关联：[第一阶段 MVP](01-第一阶段MVP.md)、[架构与分层](02-架构与分层.md)、[CMake 依赖方案](CMake依赖方案.md)

## 项目定位

DirBridge 是一个类似 Xftp 的远程文件管理工具，面向 Windows 桌面场景，目标是用图形化界面管理本地与远程文件。

核心能力：

- 本地目录和远程目录同时显示。
- FTP、FTPS、SFTP、SCP 远程连接。
- 远程目录浏览和基础文件操作。
- 上传、下载、跨远程传输队列。
- 多标签页和会话管理。
- 日志、配置和后续远程编辑能力。

## 技术栈

- 语言标准：C++17
- UI：Qt 5 / Qt 6 / Qt Widgets
- 构建：CMake
- 协议：libcurl
- 配置：nlohmann/json
- 日志：spdlog

第一阶段不引入：

- libssh2
- SQLite
- 插件系统
- 内置编辑器

## 架构原则

核心原则：

- Qt 只负责 UI 和桌面交互。
- Core 层保持纯 C++，不依赖 Qt。
- Protocol 层独立封装 libcurl。
- Config 层使用 nlohmann/json。
- Logging 层使用 spdlog。
- UI 不直接调用 libcurl，不直接读写配置文件。

分层结构：

```text
Qt UI 层
    ↓
Core 核心层
    ↓
Protocol 协议层
    ↓
Config / Logging 基础设施
```

当前已有 Qt UI 原型可继续保留，但新增业务逻辑优先落到纯 C++ Core 中。

## 阶段路线

### MVP

先验证 Xftp 主流程：

- 本地文件浏览。
- 站点配置基础设施。
- 远程连接和目录浏览。
- 上传、下载和传输队列。
- 日志可写入文件并在 UI 中展示。

### 第一阶段后半段

在主流程跑通后补齐：

- 远程编辑，使用外部编辑器和缓存目录。
- 权限查看和修改，按协议能力启用或禁用。
- 更完整的失败重试、取消、传输状态恢复。

### 第二阶段

面向效率增强：

- 文件夹比较。
- 单向目录同步。
- 同步浏览。
- 断点续传 UI。

### 第三阶段

面向扩展能力：

- SSH 终端。
- 文件预览。
- SQLite 历史记录。

### 第四阶段

长期探索：

- 插件系统。
- WebDAV、S3、OSS、COS、MinIO 等扩展协议。

## 构建兼容策略

- 项目保持 C++17，不为旧编译器降低标准。
- 编译器必须提供可用的 `<filesystem>`；GCC 7.3 / 旧版 MinGW 不在支持范围内。
- CMake 优先按 `Qt${QT_VERSION_MAJOR}` 链接 Qt 5 或 Qt 6，不默认限定 Qt 6。
- Qt5/Qt6 的小型 API 差异优先在局部使用条件编译处理；只有差异扩大到多处重复时再考虑兼容层。
