# 03-远程文件外部编辑

关联：[总体技术方案](00-总体技术方案.md)、[架构与分层](02-架构与分层.md)

## 功能说明

DirBridge 通过 Windows 默认关联应用编辑远程文件，不内置文本编辑器。

在远程文件列表中选择普通文件并执行“编辑”后，DirBridge 会将文件下载到当前用户应用数据目录下的独立缓存，再用系统默认应用打开。外部应用保存缓存文件后，DirBridge 会等待写入稳定、创建上传快照并自动同步回原远程路径。

## 使用边界

- 首个版本最多编辑 5 MiB 的远程文件。
- 同一会话和远程路径只保留一个编辑会话；不同文件和不同会话使用隔离缓存。
- 缓存工作副本使用经 Windows 文件名规则清理后的远程原文件名；会话和文档目录仍使用隔离键，避免同名文件冲突。
- 编辑下载和自动同步不会作为普通传输队列任务显示。
- DirBridge 不解析、转换或重写文件正文，编码、换行和编辑器能力由外部应用决定。
- 外部应用可能通过临时文件替换原文件，因此 DirBridge 同时监听缓存文件和父目录。

## 同步与异常处理

- 本地保存后，DirBridge 先生成稳定快照，再后台上传；上传过程中再次保存会在当前上传结束后继续同步最新版本。
- 只有远程后端明确返回成功后，DirBridge 才会刷新当前远程目录，因此文件大小、修改时间等列表信息会更新。
- 编辑准备、同步、失败和冲突信息记录在日志中，不增加文件列表状态列。
- 上传失败或检测到可能的远程冲突时，本地缓存会保留，且不会自动覆盖远程文件。
- 仅正在编辑的远程文件右键菜单显示“关闭编辑”；该操作停止监听和后续自动同步，但不删除编辑缓存。
- 最多同时编辑 5 个远程文件；打开第 6 个文件时会自动停止最久未成功同步文件的监听，但保留其缓存。
- 编辑首次打开和每次成功同步后重新计时；连续 5 分钟没有成功同步时自动停止该文件的监听，但保留缓存。
- 关闭远程会话或主程序会停止相关监听，但不会删除编辑缓存。

## 已知限制

- 冲突检测依赖 FTP/SFTP 服务端返回的大小和修改时间，只能尽力检测，不能保证覆盖所有并发修改。
- DirBridge 无法可靠知道 VS Code、Notepad++ 等默认应用何时真正退出；关闭会话后不会继续监听该缓存文件。
- 不提供自动合并、多人协作、外部编辑器进程控制或跨重启自动恢复。
