# 技术选型-远程传输库

关联：[[XFolder]]、[[Xftp界面拆解]]、[[架构草案]]、[[CMake依赖方案]]

## 结论

XFolder 第一版推荐使用 `libcurl` 作为远程传输主库，通过统一后端封装 FTP、FTPS、SFTP 等协议。旧 `CBB_SFTP` 中的 QSsh 经验可作为 UI 行为、拖拽下载和远程编辑流程参考，但不作为新项目主线。

选择原因：

- 一个库覆盖 FTP、FTPS、SFTP、SCP 等核心远程文件协议，减少多库组合带来的错误模型和任务调度分裂。
- 官方提供 easy interface 和 multi interface，后者适合传输队列、多任务并发、非阻塞调度。
- CMake 官方模块 `FindCURL` 支持 `CURL::libcurl` 导入目标，并可检查可用协议和特性。
- 生态成熟，Windows、Linux、macOS 上都有大量现成构建方式。

需要注意：

- libcurl 是传输库，不是文件管理器框架。XFolder 仍需要自己设计文件列表模型、面板状态、拖拽行为、传输队列和会话管理。
- libcurl 的具体构建可以裁剪协议。CMake 配置阶段必须检查当前 libcurl 是否启用了 FTP 和 SFTP。
- SFTP 能力依赖 libcurl 构建时启用 SSH 后端，Windows 上安装依赖时要确认包配置。

## 方案对比

| 方案 | 覆盖协议 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| `libcurl` | FTP、FTPS、SFTP、SCP、SMB 等 | 一个库覆盖 FTP/SFTP；CMake 支持好；传输、认证、代理、断点续传、错误码成熟；适合任务队列 | 不是文件管理器 API，需要自己封装目录模型、任务模型、远程操作 | 推荐主线 |
| `libssh2` | SSH2、SFTP、SCP | SFTP 控制细；BSD 许可；CMake 支持 | 不支持 FTP，需要另配 FTP 库；API 偏底层 | 适合专门做 SFTP 后端 |
| `libssh` | SSH、SFTP、SCP | SSH 能力强，适合后续终端、命令、认证增强 | 不支持 FTP；安全更新和兼容性需要持续跟进 | 适合 SSH/终端能力增强 |
| `POCO FTPClientSession + libssh2/libssh` | FTP + SFTP | C++ 风格，FTP API 直观 | 两套库组合，错误模型、连接状态和任务调度要统一 | 可作为 libcurl 不合适时的备选 |
| Qt 自实现 FTP | FTP | 与 Qt 信号槽天然融合，可适配特殊设备 | FTP 状态机、PASV、MLSD/LIST、编码、异常兼容都要自己维护 | 不推荐第一版主线 |
| QSsh | SFTP/SSH | 旧项目已有经验 | 不覆盖 FTP；后续维护和生态不如主流库清晰 | 只作为旧代码参考 |
| WinSCP .NET/COM/CLI | FTP/SFTP/SCP/WebDAV/S3 | Windows 下功能完整，自动化成熟 | 更像调用外部工具，不适合作为 Qt C++ 内嵌核心库 | 不作为主线，可用于批处理参考 |

## 为什么说 libcurl 成熟

libcurl 官方定位是客户端 URL 传输库，协议覆盖面很广，包含 XFolder 第一阶段需要的 FTP、FTPS、SFTP、SCP。它长期保持稳定 API/ABI，跨平台，文档完整，适合把协议传输能力作为底层积木。

对 XFolder 更关键的是 `multi interface`。Xftp 类工具需要同时处理多个上传、下载、远程到远程中转任务，如果每个传输都阻塞一个 UI 操作，界面会很快失控。libcurl multi interface 的职责正是管理多个并发 transfer，让应用层可以把它接到 `TransferManager` 和 Qt 事件循环中。

CMake 集成也比较直接。`FindCURL` 提供 `CURL::libcurl` 导入目标，还支持按组件请求协议或特性。XFolder 应在配置阶段检查 `FTP` 和 `SFTP`，避免用户链接到一个不支持目标协议的 libcurl 构建。

## 推荐落地策略

第一阶段：

- 使用 `libcurl` 做 FTP/SFTP 上传、下载、目录列表、删除、重命名、新建目录。
- 封装 `CurlRemoteBackend`，不要让 UI 或传输队列直接依赖 libcurl 细节。
- 所有传输都抽象为 `TransferJob`，由 `TransferManager` 统一调度。
- 跨远程拖拽第一版走本地临时中转，不依赖 FTP FXP 或服务器端复制。

第二阶段：

- 增加 FTPS、代理、编码设置、连接保活、断点续传。
- 针对特殊设备保留协议适配层，例如某些设备 LIST 输出异常时增加解析策略。
- 如果要做 SSH 终端，再评估 `libssh` 或专门的 SSH 会话后端。
