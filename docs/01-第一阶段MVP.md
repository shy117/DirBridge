# 01-第一阶段MVP

关联：[总体技术方案](00-总体技术方案.md)、[架构与分层](02-架构与分层.md)

## 阶段目标

第一阶段 MVP 的目标是做出 Xftp 风格的远程文件管理主流程，而不是一次性实现所有高级功能。

本阶段应保证：

- 用户可以浏览本地目录和远程 FTP/SFTP 目录。
- 用户可以保存、加载和管理站点配置。
- 用户可以上传、下载、删除、重命名和新建基础文件项。
- 用户可以看到传输任务状态、进度和失败原因。
- 用户可以同时打开多个远程会话，并区分每个会话的当前路径和传输来源。
- 应用可以记录日志，便于排查连接、传输和配置问题。

## 功能范围

### UI

- 主界面采用本地面板、远程会话面板、会话管理器、传输队列和日志区域。
- 本地和远程文件面板采用“地址栏 + 文件树 + 详细信息列表”结构。
- 文件列表通过表头排序，不在右键菜单中提供排序菜单。
- 常用文件操作放在文件列表右键菜单中，连接入口放在快速连接栏和会话管理器中。
- 远程会话使用 Tab 管理；关闭会话、断开、重连只作用于当前远程会话。
- 底部只保留 `传输` 和 `日志`，后续功能稳定后再评估是否增加其他面板。

### Core

- 保持纯 C++17，不依赖 Qt Widgets。
- 提供文件条目模型、站点配置模型、传输任务模型和传输队列状态模型。
- 传输任务需要支持等待、运行、完成、失败、取消、重试和清理已完成任务。
- 目录传输使用父任务表示整体进度，子任务保留具体文件明细。

### Protocol

- 通过远程文件系统抽象接入 FTP/SFTP。
- Protocol 层封装 libcurl 细节，不向 UI 暴露 libcurl API。
- 远程文件操作覆盖连接、列目录、上传、下载、新建目录、新建文件、删除和重命名。
- 远程目录列表优先使用详细信息；无法解析时允许回退到基础名称列表。

### Config

- 使用 JSON 保存站点配置和用户设置。
- 站点配置至少包含协议、主机、端口、用户名、密码保护字段、默认远程路径、编码和分组。
- 站点密码落盘时使用 Windows 当前用户 DPAPI 加密；旧版明文配置可兼容读取并在下次保存时迁移。
- 最近会话只用于显示近期入口，不用于启动自动重连。

### Logging

- 使用 spdlog 写入本地日志文件。
- 日志至少覆盖启动、依赖检查、站点加载、连接、传输和错误信息。
- UI 日志面板显示用户能理解的关键事件；内部诊断细节保留在日志文件中。

## 验收场景

1. 用户打开软件，看到本地文件面板、会话管理器、传输队列和日志区域。
2. 用户新建并保存 FTP/SFTP 站点，重启后仍能加载。
3. 用户连接 FTP/SFTP 站点，远程面板显示目录内容。
4. 用户可以进入远程目录、返回上级、刷新当前远程目录。
5. 用户可以上传本地文件或文件夹到远程目录。
6. 用户可以下载远程文件或文件夹到本地目录。
7. 目录传输显示整体进度，并允许展开查看子文件明细。
8. 用户可以对远程文件项执行新建、删除、重命名等基础操作。
9. 多个远程会话互不影响，当前会话的断开、重连和关闭只作用于当前 Tab。
10. 连接失败、传输失败或配置异常时，界面和日志都能提供可理解的信息。
