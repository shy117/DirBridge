# 01-第一阶段MVP

关联：[[00-总体技术方案]]、[[02-架构与分层]]

## MVP 目标

MVP 目标是先做出 Xftp 风格的可用主流程，而不是一次性塞满所有高级功能。

必须验证：

- 本地目录可以浏览。
- 远程目录可以浏览。
- 站点配置可以保存和加载。
- 文件可以上传和下载。
- 传输任务进入队列并显示状态。
- 基础日志能写入文件并给 UI 使用。

### Config

- 使用 JSON 保存站点配置。
- 使用 JSON 保存用户设置。
- 第一阶段可先明文保存密码，文档和 UI 必须标注风险。

当前站点配置文件：

```text
config/sites.json
```

当前字段：

- `id`
- `name`
- `protocol`
- `host`
- `port`
- `username`
- `password`
- `defaultRemotePath`
- `encoding`

`passwordStorage` 当前为 `plain-text`，只用于本地开发验证。

### Logging

- 使用 spdlog 写入本地日志文件。
- 日志至少包含启动、依赖检查、连接、传输、错误信息。
- 当前 UI 日志面板已显示启动、依赖检查、站点加载、快速连接和远程目录加载信息。

当前日志文件：

```text
logs/dirbridge.log
```

## 第一阶段后半段

主流程稳定后再实现：

- 远程编辑：下载到缓存目录，外部编辑器打开，检测修改，提示上传。
- 权限管理：查看权限，按协议能力启用 chmod 或禁用。
- 更细的任务取消、重试、失败恢复。

## 验收场景

1. 用户打开软件，看到左本地、右远程、会话管理器、传输队列和日志区域。
2. 用户保存一个站点配置，重启后仍能加载。
3. 用户连接 FTP 或 SFTP，远程面板显示目录。
4. 用户从本地拖文件到远程，生成上传任务并完成。
5. 用户从远程拖文件到本地，生成下载任务并完成。
6. 连接失败或传输失败时，UI 和日志都能显示可理解的错误。
