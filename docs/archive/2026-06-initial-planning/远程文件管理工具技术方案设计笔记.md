# 远程文件管理工具技术方案设计笔记 V1

## 一、项目定位

开发一款类似 Xftp 的远程文件管理工具。

目标：

* 支持 FTP / FTPS / SFTP / SCP
* 图形化远程文件管理
* 文件上传下载
* 文件权限管理
* 远程编辑
* 多标签页
* 传输队列管理

设计原则：

> Qt 仅作为 UI 框架，核心业务逻辑不依赖 Qt。

---

┌─────────────────────┐

# 三、技术选型

## C++标准

推荐：

```text
C++17
```

原因：

* std::filesystem
* std::optional
* std::variant
* std::string_view
* 结构化绑定
* if constexpr

优点：

* 足够现代
* 编译器兼容性成熟
* 第三方库支持广泛

不推荐：

```text
C++11
```

原因：

* 标准库能力不足
* 开发效率较低

暂不强制：

```text
C++20
```

原因：

* 第一阶段收益有限
* 编译环境要求更高

---

# 四、协议库方案

## 第一阶段

采用：

```text
libcurl
```

支持协议：

* FTP
* FTPS
* SFTP
* SCP

优势：

* 一套接口支持多协议
* 成熟稳定
* 文档丰富
* 社区活跃

第一阶段全部协议统一使用 libcurl。

---

## 关于 libssh2

当前结论：

```text
第一阶段不引入 libssh2
```

原因：

* 与 libcurl 功能重叠
* 增加架构复杂度
* 增加维护成本

设计原则：

```text
架构允许未来引入
当前不实际依赖
```

未来场景：

* SSH终端
* 高级SFTP特性
* 深度SSH能力

可考虑增加 libssh2 Backend。

# 五、统一远程文件系统接口

设计目标：

协议层对上层透明。

Core层和UI层不直接感知：

```text
FTP
FTPS
SFTP
SCP
libcurl
libssh2
```

统一抽象：

```text
IRemoteFileSystem
```

职责：

* 连接
* 列目录
* 上传
* 下载
* 删除
* 重命名
* 创建目录
* 获取文件信息
* 修改权限

架构：

```text
Qt UI
   ↓
Core
   ↓
IRemoteFileSystem
   ↓
CurlRemoteFileSystem
   ↓
libcurl
```

未来：

```text
IRemoteFileSystem
│
├── CurlRemoteFileSystem
└── Ssh2RemoteFileSystem
```

优势：

* 解耦协议实现
* 方便替换底层库
* 支持未来扩展协议

# 九、远程编辑功能

定位：

第一阶段实现。

实现方式：

```text
远程文件
   ↓
下载到缓存目录
   ↓
调用系统默认编辑器
   ↓
监听文件变化
   ↓
提示上传
   ↓
重新上传远程服务器
```

流程：

```text
打开文件
↓
缓存文件
↓
外部编辑器编辑
↓
检测修改
↓
上传
↓
结束监听
```

第一阶段目标：

* 外部编辑器打开
* 文件变化检测
* 上传确认
* 缓存管理

暂不实现：

* 内置编辑器
* 自动实时同步
* 冲突合并

# 十二、第二阶段规划

## 文件夹比较（Folder Compare）

功能：

比较本地目录和远程目录。

示例：

```text
本地：
D:\website

远程：
/var/www/html
```

比较结果：

```text
相同
本地较新
远程较新
仅本地存在
仅远程存在
```

比较依据：

* 文件名
* 文件大小
* 修改时间
* MD5（可选）

价值：

★★★★★

---

## 目录同步（Directory Sync）

功能：

保持本地和远程目录一致。

模式：

### 单向同步

```text
本地 → 远程
```

适合：

* 网站发布
* 项目部署

---

### 双向同步

```text
本地 ↔ 远程
```

后续实现。

需要解决：

* 冲突检测
* 版本判断

价值：

★★★★★

---

## 同步浏览

功能：

```text
本地切换目录
↓
远程自动切换对应目录
```

例如：

```text
本地：
/project/src

远程：
/var/www/src
```

价值：

★★★★☆
