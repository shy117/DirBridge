# 架构草案

关联：[[XFolder]]、[[技术选型-远程传输库]]、[[Xftp界面拆解]]

## 总体思路

XFolder 按“文件面板 + 文件系统后端 + 传输队列”设计。UI 不直接关心 FTP、SFTP 或本地文件 API，只面对统一的文件系统接口。

核心目标：

- 本地目录和远程目录使用同一套面板交互。
- FTP/SFTP 差异封装在远程后端中。
- 拖拽不直接执行文件复制，而是生成传输任务。
- 多远程目录之间传输由 `TransferManager` 统一调度。

## 模块划分

```text
MainWindow
├── SessionManagerView
├── FileWorkspace
│   ├── FilePanel(Local)
│   └── FilePanel(Remote...)
└── TransferQueueView

Core
├── SessionManager
├── TransferManager
├── FileSystemBackend
│   ├── LocalFileSystemBackend
│   └── CurlRemoteBackend
└── Models
```

## MainWindow

职责：

- 管理主窗口布局。
- 管理菜单栏、工具栏、快速连接栏。
- 管理会话管理器、文件工作区、传输队列和日志。
- 协调打开会话、关闭会话、创建远程标签页。

MainWindow 不直接执行文件传输，也不直接调用 libcurl。

## FilePanel

`FilePanel` 是一个目录浏览面板，可以绑定本地后端或远程后端。

职责：

- 显示当前路径。
- 显示文件表格。
- 处理返回、前进、上级、刷新。
- 处理右键菜单。
- 发起拖拽。
- 接收拖拽。

FilePanel 只产生用户意图，例如：

- 打开目录
- 删除文件
- 重命名
- 上传到此目录
- 下载到此目录
- 跨远程复制到此目录

真正的执行交给后端或 `TransferManager`。

## FileSystemBackend

统一文件系统接口，覆盖本地和远程。

建议能力：

- 列目录
- 创建目录
- 删除文件
- 删除目录
- 重命名
- 获取文件信息
- 判断路径类型

上传、下载、跨后端复制不直接放在基础接口里，而是交给 `TransferManager` 创建任务。

## LocalFileSystemBackend

基于 Qt 本地文件 API 实现。

职责：

- 使用 `QDir`、`QFileInfo`、`QFile` 操作本地文件。
- 提供本地文件列表。
- 提供本地复制、删除、重命名支持。

## CurlRemoteBackend

基于 libcurl 实现 FTP/SFTP 后端。

职责：

- 管理远程会话配置。
- 执行目录列表。
- 执行远程新建目录、删除、重命名。
- 为 `TransferManager` 提供上传、下载能力。
- 将 libcurl 错误转换为业务错误。

注意：

- UI 和 FilePanel 不应包含 libcurl 头文件。
- libcurl easy/multi 的细节限制在 backend 层或 transfer 层。

## TransferManager

传输队列核心。

职责：

- 接收上传、下载、远程到远程、本地复制任务。
- 控制并发数量。
- 维护任务状态。
- 上报进度、速度、剩余时间。
- 支持取消、暂停、继续、重试。
- 管理远程到远程传输的本地临时中转文件。

任务类型：

- Upload
- Download
- RemoteToRemote
- LocalCopy
- LocalMove

任务状态：

- Pending
- Running
- Paused
- Completed
- Failed
- Canceled

## SessionManager

职责：

- 保存常用会话。
- 加载会话配置。
- 创建远程后端。
- 打开远程标签页。

第一版配置文件可使用 JSON 或 INI。因为 Qt 对 INI 支持直接，第一版推荐使用 `QSettings` 保存到 `config/sessions.ini`。

## 数据模型

建议通用文件信息：

```cpp
struct FileItem
{
    QString name;
    QString path;
    quint64 size;
    QDateTime modifiedAt;
    FileItemType type;
    QString permissions;
    QString owner;
    QString group;
};
```

建议面板位置：

```cpp
struct PanelLocation
{
    QString backendId;
    QString path;
};
```

建议传输任务：

```cpp
struct TransferRequest
{
    PanelLocation source;
    PanelLocation target;
    QStringList itemPaths;
    TransferMode mode;
};
```

具体类型后续写代码时再落地，本阶段只固定职责边界。

## 旧项目复用方式

旧 `CBB_SFTP` 可参考：

- Qt Widgets 主窗口组织。
- 远程文件列表行为。
- 拖拽到 Windows 资源管理器。
- 文件图标缓存。
- 临时文件管理。

不直接复用：

- `QSsh::SftpJobId`
- `QSsh::SftpFileInfo`
- `form_sftp` 直接持有 `Mod_Sftp` 的耦合方式
