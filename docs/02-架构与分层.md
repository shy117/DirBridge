# 02-架构与分层

关联：[[00-总体技术方案]]、[[01-第一阶段MVP]]

## 目录原则

建议源码结构：

```text
src/
├── app/          Qt 应用入口
├── ui/           Qt Widgets 界面
├── core/         纯 C++ 业务模型和调度
├── protocol/     libcurl 等协议封装
├── config/       JSON 配置读写
└── logging/      spdlog 日志封装
```

## UI 层

目录：`src/ui`

职责：

- 主窗口布局。
- 文件面板显示。
- 会话管理器显示。
- 传输队列和日志面板显示。
- 用户输入、菜单、按钮、拖拽事件。

限制：

- 不直接调用 libcurl。
- 不直接读写 JSON 配置文件。
- 不直接管理传输状态机。
- 不承载可复用业务规则。

当前 `FilePanel` 中的本地文件浏览逻辑属于 UI 原型，后续逐步迁移到 Core 的本地文件系统接口。

## Core 层

目录：`src/core`

职责：

- 文件模型。
- 站点模型。
- 传输任务模型。
- 传输队列调度。
- 远程文件系统统一接口。
- 错误模型。

要求：

- 使用标准 C++17。
- 不依赖 Qt。
- 不包含 QWidget、QString、QDir 等 Qt 类型。
- 对 UI 暴露稳定、可测试的业务接口。

## Protocol 层

目录：`src/protocol`

职责：

- 封装 libcurl。
- 提供 FTP、FTPS、SFTP、SCP 的统一远程文件系统实现。
- 将 libcurl 错误码转换成 Core 错误。
- 暴露协议能力，例如是否支持 chmod、是否支持断点续传。

限制：

- UI 不包含 libcurl 头文件。
- Core 只依赖协议抽象，不依赖具体 libcurl 调用细节。

## Config 层

目录：`src/config`

职责：

- 使用 nlohmann/json 保存和加载配置。
- 管理站点配置、用户设置、收藏夹、最近连接。
- 提供配置 schema 的默认值和迁移入口。

第一阶段文件：

```text
config/sites.json
config/settings.json
config/bookmarks.json
```

## Logging 层

目录：`src/logging`

职责：

- 初始化 spdlog。
- 写入应用日志文件。
- 为 UI 日志面板提供日志事件。
- 管理日志等级和日志轮转。

第一阶段日志路径：

```text
logs/xfolder.log
```

## 依赖方向

允许：

```text
ui -> core
ui -> logging facade
core -> protocol abstraction
core -> config
protocol -> libcurl
config -> nlohmann/json
logging -> spdlog
```

禁止：

```text
core -> Qt Widgets
ui -> libcurl
ui -> nlohmann/json 文件读写细节
protocol -> QWidget
```
