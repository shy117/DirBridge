# 三方库管理

关联：[CMake 依赖方案](CMake依赖方案.md)、[运行环境说明](运行环境说明.md)

## 管理原则

三方库文件不提交到 Git。仓库只提交：

- `deps.lock.json`
- `scripts/setup_third_party.ps1`
- CMake 配置
- 文档

克隆仓库后通过脚本复原依赖环境。

## 目录结构

```text
third_party/
├── _downloads/
├── _source/
└── installed/
    ├── curl/
    │   ├── include/
    │   ├── lib/
    │   └── bin/
    ├── nlohmann_json/
    │   └── include/
    └── spdlog/
        └── include/
```

说明：

- `_downloads` 保存下载包。
- `_source` 保存解压后的原始源码或发布包。
- `installed` 是项目实际引用的安装态依赖。

CMake 只允许引用 `third_party/installed`，不直接引用 `_source`。

## 当前依赖

依赖版本锁定在 `deps.lock.json`：

- curl `8.20.0_5` Windows MinGW 预编译包。
- nlohmann/json `3.12.0`。
- spdlog `1.17.0`。

当前脚本准备的 libcurl 包面向 MinGW，包含 `libcurl.dll.a` 和 `libcurl-x64.dll`。如果使用 MSVC 构建，需要准备匹配 MSVC ABI 的 libcurl，或后续迁移到 vcpkg 等统一依赖管理方案。

## 初始化命令

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_third_party.ps1
```

强制重新下载和整理：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_third_party.ps1 -Force
```

## Git 策略

`third_party/` 整体被 `.gitignore` 排除。这样仓库不会包含三方源码、头文件、lib 或 dll。

如果要迁移到新机器：

1. 克隆仓库。
2. 运行 `scripts/setup_third_party.ps1`。
3. 执行 CMake configure 和 build。
