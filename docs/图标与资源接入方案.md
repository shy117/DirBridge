# 图标与资源接入方案

关联：[总体技术方案](00-总体技术方案.md)、[第一阶段 MVP](01-第一阶段MVP.md)、[CMake 依赖方案](CMake依赖方案.md)、[三方库管理](三方库管理.md)

## 目标

为 DirBridge 引入统一的应用图标、Logo 和通用操作图标资源，满足以下需求：

- Windows 窗口图标。
- Windows exe 文件图标。
- Qt 运行时资源引用。
- 后续菜单、工具栏、状态提示图标复用。
- 保留 Fluent UI System Icons 的许可证说明。
- 不在运行时联网加载图标。
- 不把 npm 作为 Qt 项目的长期依赖。

本方案只定义资源组织和接入路径，不改变 Core、Protocol、Config、Logging 等业务分层。

## 资源阶段

### 概念图阶段

当前 AI 生成图片用于确认方向，包括图形语言、横竖排版、颜色和字体感觉。

概念图阶段可以接受以下限制：

- 图片是位图，不是正式矢量源文件。
- 边缘、阴影和文字可能不够干净。
- 棋盘格背景可能只是预览，也可能已经被写入 PNG 像素。
- 不直接作为长期可维护的最终 Logo 源文件。

### 可用位图阶段

确认概念图后，先制作可实际用于 Qt 和 Windows 的位图资源：

- 去除背景，生成透明 PNG。
- 裁切有效内容，并保留统一安全边距。
- 导出多尺寸 PNG，例如 `1024x1024`、`512x512`、`256x256`、`128x128`、`64x64`、`48x48`、`32x32`、`16x16`。
- 用多尺寸 PNG 合成 `dirbridge.ico`。
- 保留高清 `dirbridge_logo.png`，用于 README、关于窗口或发布说明。

### 正式矢量阶段

长期使用的正式 Logo 应重新绘制为干净 SVG，而不是把 AI 位图直接嵌入 SVG。

推荐做法：

- 用 SVG path 绘制文件夹轮廓。
- 用统一粗细的路径绘制桥梁线条。
- 用圆形和弧线绘制连接节点与信号符号。
- 用 `linearGradient` 还原蓝色渐变。
- 控制视图框、边距、圆角、描边和缩放表现。
- 文字部分使用明确字体排版，发布前可按需要转曲。

自动描摹 PNG 可作为参考草稿，但不建议作为最终 SVG，因为路径容易碎片化，渐变、阴影和文字也难以维护。

## Windows rc 示例

```rc
IDI_ICON1 ICON DISCARDABLE "../icons/app/dirbridge.ico"
```

`resources.qrc` 负责 Qt 运行时资源，`.rc` 负责 Windows exe 文件图标。两者用途不同，不能互相替代。

## CMake 接入点

当前工程已启用：

```cmake
set(CMAKE_AUTORCC ON)
```

因此可以把 qrc 加入 `DirBridge` 目标：

```cmake
add_executable(DirBridge
    src/app/main.cpp
    src/ui/MainWindow.cpp
    src/ui/MainWindow.h
    src/ui/FilePanel.cpp
    src/ui/FilePanel.h
    resources/resources.qrc
)
```

Windows exe 图标可通过 `.rc` 接入：

```cmake
if(WIN32)
    target_sources(DirBridge PRIVATE
        resources/windows/dirbridge.rc
    )
endif()
```

如果直接使用 SVG 作为 Qt 图标资源，建议补充 QtSvg：

```cmake
find_package(Qt${QT_VERSION_MAJOR} REQUIRED COMPONENTS Widgets Svg)
```

并链接：

```cmake
target_link_libraries(DirBridge
    PRIVATE
        Qt${QT_VERSION_MAJOR}::Widgets
        Qt${QT_VERSION_MAJOR}::Svg
        DirBridgeCore
)
```

QtSvg 属于 Qt 自身模块，不是额外三方库；但发布包需要验证 SVG 相关运行时库和插件是否被正确部署。

## Qt 代码接入点

应用级图标可在 `src/app/main.cpp` 中设置：

```cpp
QApplication app(argc, argv);
app.setWindowIcon(QIcon(":/icons/app/dirbridge.ico"));
```

主窗口也可以显式设置窗口图标：

```cpp
setWindowIcon(QIcon(":/icons/app/dirbridge.ico"));
```

推荐两处都设置：

- `QApplication::setWindowIcon` 负责应用默认图标。
- `MainWindow::setWindowIcon` 明确设置主窗口图标。

## 建议修改顺序

### 第一步：接入应用图标

影响文件：

```text
CMakeLists.txt
src/app/main.cpp
src/ui/MainWindow.cpp
resources/resources.qrc
resources/windows/dirbridge.rc
resources/icons/app/*
```

验证目标：

- 程序窗口显示 DirBridge 图标。
- Windows exe 文件显示 DirBridge 图标。
- 构建通过。
- smoke test 通过。

### 第二步：接入 Fluent 图标资源

影响文件：

```text
CMakeLists.txt
resources/resources.qrc
resources/icons/fluent/*
resources/licenses/FluentUI-System-Icons-LICENSE.txt
docs/运行环境说明.md
```

验证目标：

- Qt 能加载 SVG 图标。
- 打包后 SVG 图标正常显示。
- license 文件保留。

### 第三步：替换部分 UI 图标

优先替换：

```text
FilePanel:
```

## 验证命令

```powershell
cmake --build build\codex-verify
.\build\codex-verify\DirBridge.exe --check-deps
.\build\codex-verify\DirBridge.exe --smoke-test
git diff --check
```

如果接入 SVG 后出现图标不显示，优先检查：

- 是否链接了 QtSvg。
- QtSvg 运行时 DLL 是否被部署。
- SVG icon engine 插件是否被部署。
- `resources.qrc` 路径是否正确。
- `:/icons/...` 资源路径是否与 qrc prefix 一致。

## 风险点

1. AI PNG 可能不是真透明。
   需要先检测 alpha 通道，必要时去背景。

2. `.ico` 不能只用单一尺寸。
   应包含多个尺寸，否则小图标会模糊。

3. SVG 图标需要 QtSvg 支持。
   开发机正常不代表发布包正常，需要部署验证。

4. Fluent 图标许可证必须保留。
   放入 `resources/licenses/`，并在文档中说明来源和用途。

5. 不建议一次性替换所有图标。
   先完成应用图标，再逐步替换工具栏和菜单图标。

## 推荐结论

先做应用图标最小闭环：

1. 选定无文字概念图作为应用图标基础。
2. 生成透明 PNG。
3. 生成多尺寸 `.ico`。
4. 创建 `resources.qrc`。
5. 创建 Windows `.rc`。
6. 设置 `QApplication` 和 `MainWindow` 图标。
7. 构建并验证。

Fluent 图标作为第二阶段接入，避免应用图标和 UI 图标替换混在一个改动里。
